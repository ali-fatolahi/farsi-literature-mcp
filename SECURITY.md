# Security Policy

## Supported versions

The project currently supports the latest `main` branch and the latest released version when one is published.

## Reporting a vulnerability

Please do not open a public issue for security vulnerabilities.

To report a security issue, contact the repository owner privately by email or through GitHub private reporting if enabled. Include:

- a concise summary of the vulnerability
- affected files, commit, or release
- reproduction steps or proof of concept
- impact and risk assessment
- any suggested mitigation

We will review the report and respond as quickly as practical. We expect to acknowledge reports promptly and to coordinate a fix and disclosure timeline with the reporter when appropriate.

## Disclosure policy

We aim to fix validated security issues promptly. Public disclosure will happen only after a fix is available or after a reasonable coordination window has ended.

## Security expectations

Contributors should avoid introducing remote-code execution, credential leakage, unsafe file handling, external network access without clear need, or unreviewed execution of user-supplied files.

This project expects valid provenance and source attribution for all retrieved text and metadata, and it should not silently expose private or account-linked data from upstream sources.
